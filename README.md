# 拾刻

面向 Windows 的 PoE 工具箱，提供洗词缀、连点器、按键循环和一键回城。使用 C#、.NET 10 与原生 WPF 实现。

## 运行与更新

完整解压维护者提供的 `拾刻-win-x64.zip`，运行 `拾刻.exe`。需要安装 **[x64 .NET 10 桌面运行时](https://dotnet.microsoft.com/zh-cn/download/dotnet/10.0)**：在微软官网选择“.NET 桌面运行时”下的 Windows x64 安装程序。

启动后先检查「设置」中的目标游戏进程，再启用需要的工具。游戏使用管理员权限时，拾刻也应使用相同权限；窗口标题会显示本次运行的实际权限状态。

启动发现新版后保持强制更新：提示后退出，不能继续使用旧版主页面。支持新式签名清单时，程序校验 ZIP 后由独立临时助手按文件清单更新，成功启动并确认新版后才启用工具；失败恢复本次变更并退出。旧式清单仍打开固定 ZIP 下载入口后退出。

日常更新默认只替换变化的主 EXE；文件清单也可明确更新根目录 DLL 和内置音频。未变化文件跳过，未列文件不写入；既有资源必须匹配可信旧版哈希，用户改过的资源发生冲突时停止整批更新。**整个 `data` 目录、配置、规则、坐标和个人预设不进入更新目标**。首次从没有自动更新能力的旧版过渡，仍需手动替换一次主 EXE，保留原 data 和自定义音效。

## 使用

### 洗词缀

选择模式和通货 → 点击「设定坐标」，鼠标移到游戏中的目标后按 **F7** → 填写词缀 → 切回游戏按 **F5** 开始、**F6** 停止。界面保留原通货坐标卡；Mode2实际只要求装备和改造石／点金石坐标，配对的增幅／重铸通过游戏Alt快捷操作自动使用。

| 模式 | 规则 |
| --- | --- |
| Mode 1 单通货 | 主词缀池任意命中 1 条即停止，不用设置主／次数量 |
| Mode 2 | 改造＋增幅，或重铸＋点金；主＋次要求最多 2 条。持续按住Shift，以Alt临时使用增幅／重铸，结束后恢复改造／点金。改造出了两条词缀会直接终检，不再增幅 |
| Mode 3 | 改造＋增幅＋富豪；主＋次要求最多 3 条。魔法阶段按总命中数减 1 筛选，富豪后终检；未成功会重铸重来。崇高可选，启用后补录其坐标 |

Mode 2/3 在词缀池标题旁选择命中数，超限会在启动时弹窗提醒。例如要 A＋B/C：主池放 A、主 1，次池放 B 和 C、次 1。

- 单通货下拉框选择币种，通货卡片负责录制坐标。移动装备／通货、改变游戏窗口或分辨率后，重新确认坐标。
- 洗装统一使用Ctrl+C复制高级物品文本，适用于PoE 3.29及已包含该复制改动的客户端；此版本需要游戏支持Alt快捷增幅／重铸，并有可用的配对通货。
- 词缀按文字包含匹配，参考Ctrl+C复制出的实际描述填写；不自动判断数值范围或T1，装备名和基础类型也能参与匹配。同一条实际词缀不会被相近关键词重复计数。
- 排除词缀优先：改造阶段出现会继续洗，最终检查出现则不合格。
- 预设只保存词缀池和命中数，加载后仍需确认模式、通货、坐标、子模式与崇高开关。
- “物品信息未变化”也可能由坐标、通货适用性或游戏响应造成，必要时提高操作延迟。

### 其他工具

| 功能 | 默认操作 |
| --- | --- |
| 连点器 | 启用后 F8 开始／停止；按住 F11 连点，松开停止。点击鼠标当前位置，左／右键可选 |
| 按键循环 | 设置槽位按键和间隔（秒），开启槽位；F9 开始／停止，最多 10 槽 |
| 一键回城 | 启用后按 F2，默认发送 `/hideout`，命令可修改 |

热键可在「设置」中修改，以工具页顶部显示为准。点 **X** 退出全部工具；鼠标移至主屏幕左上角可触发紧急停止。

数字小键盘与键盘上方数字分别记录，例如 `NumPad1` 和 `1`。一键回城输入途中切离目标游戏时会取消本次输入，切回后需重新触发。

启动会检查版本、发送固定的匿名启动统计并获取广告；具体说明可在「设置 → 隐私与统计」查看。

## 项目结构

```text
README.md                   使用与开发入口
CHANGELOG.md                版本变化
.gitignore / .gitattributes  入库边界与文本格式
.githooks/                  提交、推送前的文件范围检查
源码/
  拾刻.csproj               WPF 桌面项目与单 EXE 发布入口
  Core/                    独立 net10.0 核心：规则、预设、连点/按键循环引擎及运行接口
  CoreTests/               仅依赖 Core 的无界面验证
  App.xaml / Bootstrapper.cs 启动入口
  Host/                     宿主、工具注册、导航与生命周期
  Services/                 输入、热键、存储、声音与网络等共享服务
  Tools/                    洗词缀、连点、按键循环、回城与设置
  Themes/                   WPF 主题与展示状态
  Properties/PublishProfiles/ 发布配置
  Tests/                    内部回归用例
  scripts/                  构建、打包与隔离验证入口
  验证内部用例.cmd           内部验证入口
  data/presets/             内置预设
  sounds/ / poe.ico         内置音效与图标
```

宿主统一管理热键、共享服务和分节存储；工具实现 `Host/ITool.cs`，通过 `Host/ToolRegistry.cs` 注册。坐标录制使用独立的 `ICoordinateProvider` 能力接口。需要后台工作的工具实现 `IToolRuntime`，明确区分正在运行和清理已完成；无后台自动操作的工具必须显式声明 `IPassiveTool`，缺失或同时声明两种能力会拒绝注册。工具 ID 不能占用旧平铺配置字段。可编辑热键通过 `IEditableHotkeyProvider` 声明，设置页自动生成对应条目。独立数据文件通过 `IToolAuxiliaryState` 参与宿主的可写退出保存。

Core 不引用 WPF 或桌面项目。页面编辑即时更新配置，运行入口读取本轮快照，不反向读取页面控件；切页和退出仍按原时机保存。连点和按键循环通过 `Core/Runtime` 中的接口请求 Windows 能力。洗装的输入/剪贴板编排保留在桌面项目，依赖 `ICraftEnvironment`；词缀、模式决策、预设和状态同步位于 Core。`ITool` 是 WPF 抽屉接口，不作为纯核心接口。项目拆分后仍使用原单 EXE 发布及更新方式。

## 构建与验证

正式版内部固定采用稳健组合时序，不提供实验档位选择；页面布局、文字和窗口标题延续v1.0.45。操作延迟仍用于点击后的首次同步等待，原配置保持。Mode2采用持续Shift和Alt配对通货，三个洗装模式统一Ctrl+C高级复制；空复制会重试当前物品，未确认变化不会跳过判定或追加通货。

每次停止后，后台将运行计数与最近物品状态保存到`data/craft-runs/`，用于故障排查，不增加页面控件或提示。历史速度实验版本及报告不由正式构建修改。自动更新复用原启动版本检查，不增加常驻轮询服务。

诊断日志写入异常会通过 Release 也有效的 `ShiKe-DiagnosticFailures` 事件源报告，运行期间最多每30秒出现一次轻提醒；退出时不新建提示窗口。独立事件通道不回写发生故障的日志队列，主日志恢复后仍记录失败摘要。旧配置的洗装延迟越界时，程序会明确告知原值和10～200ms范围内的生效值；未实际告知前保留原始持久值。

开发需要 Windows、Git 和 **[.NET 10 SDK](https://dotnet.microsoft.com/zh-cn/download/dotnet/10.0)**。在 Windows PowerShell 中进入仓库根目录：

```powershell
git config --local core.hooksPath .githooks
.\源码\验证内部用例.cmd
```

统一入口默认增量恢复依赖，依次编译并执行桌面主套件和独立 CoreTests，任一失败即整体失败；报告分别列出两套结果，不把复用用例相加当作新增覆盖。依赖已准备好时可传 `-NoRestore`。CoreTests 也可通过 `dotnet run --project .\源码\CoreTests\ShiKe.CoreTests.csproj -c Release` 单独执行。

内部用例会短暂显示独立测试窗口，不启动日常程序、不注册实际热键、不发送游戏输入、不访问真实应用服务。依赖恢复按本机 NuGet 配置进行。结果生成在 `bin/Release/net10.0-windows/验证记录/内部用例/`；`Run-ReviewPipelineChecks.ps1` 可独立验证首次恢复和两套失败聚合。

生成发布程序与分享包：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\源码\scripts\Build-Release.ps1"
```

输出统一在 `bin/Release/net10.0-windows/`。分享包仅包含 EXE、五个内置音效和一个内置预设；个人配置和自定义资源不进入包。已有日常程序运行时，发布入口会要求先退出。

已验证的 EXE 可用同一入口的 `-PackageOnly` 参数重新整理分享包。`Run-StartupChecks.ps1` 用于发布后的隔离启动与关闭验证，`Measure-Startup.ps1` 是它使用的测量脚本。

### 签名发布与文件更新

成功自动更新并重启后，程序会显示一次本次更新说明；普通启动、手动替换 EXE、更新失败或回滚不会显示。说明可滚动和复制，点击“知道了”、右上关闭或按 Esc 继续。

每次发布前同时更新 `源码/ReleaseNotes.txt` 的声明版本和本次更新内容。首行必须是 `Version: ` 加与项目 Version 相同的三段版本号，后面填写正文；版本头不会出现在弹窗正文里。构建时版本不符、正文为空或过长会直接失败，并把说明版本与文件 SHA256 绑定到 EXE 的版本资源中。打包和准备签名时再次只读核验实际 EXE，源说明被修改后必须重新构建，旧的未绑定 EXE 不能通过新的 PackageOnly/准备流程。

正文编译进 EXE，弹窗版本号取自应用版本；无需在服务器额外部署说明文件，也不修改签名清单格式。说明读取或显示失败只跳过提示，不改变已成功更新的结果。版本校验只能防止漏更新版本声明，正文是否准确仍须发布者审阅。

继续发布完整 ZIP。固定 `version.json` 保留旧客户端的 `latest/url`；新客户端验证其中 `autoUpdate` 的签名载荷，使用 `/download/releases/<版本>/shike-win-x64.zip` 不可变地址。发布包和文件清单均有大小及 SHA-256 校验；签名采用 RSA-PSS/SHA-256，公钥随客户端交付，私钥只在发布环境保存。

维护者首次用 `Initialize-ReleaseKey.ps1 -KeyPath <仓库外路径>` 建立当前 Windows 用户 DPAPI 保护的发布私钥，并将配套公钥固定在 `ReleaseTrust.cs`。日常发布不得重新生成密钥；私钥不进 Git、ZIP、版本清单或 VPS。DPAPI 文件不能直接在另一台机器解密，需要妥善保管原发布用户环境。

```powershell
.\源码\scripts\Run-ReleaseChecks.ps1
.\源码\scripts\Run-UpdateProcessChecks.ps1
.\源码\scripts\Prepare-UpdateRelease.ps1 -ZipPath <已验证ZIP> -ExePath <同一EXE> -KeyPath <发布私钥路径> -OutputDirectory <本次发布目录>
.\源码\scripts\Publish-UpdateRelease.ps1 -ReleaseDirectory <本次发布目录>
```

最后一条默认只校验本地材料并输出计划，不读取凭据或访问服务器。真正上线需显式 `-Execute`。缓存策略默认 `-CacheStrategy headers`，不需要 Cloudflare API 凭据；依靠实际生效的响应策略和普通公网下载的哈希／大小验证。选择 `-CacheStrategy cloudflare` 时才需要 `-CloudflareZoneId` 和指定环境变量中的最小权限清缓存令牌，并精确清理两个固定入口。

两种策略均先上传不可变版本包、公网核验，再切固定 ZIP 别名，最后发布版本清单；长缓存、内容不符或无法确认恢复结果都会阻断发布。`version.json` 要求 `no-store`，固定 ZIP 接受 `no-store`、完整 `no-cache` 或不被共享缓存正期限覆盖的 `max-age=0, must-revalidate`。首次改变缓存策略还要处理旧缓存迁移，当前一次请求不能证明所有浏览器的历史缓存均已清空。显式发布回退使用 `-Rollback -Transaction <已记录事务标识> -Execute -CacheStrategy <策略>`，旧包和旧清单仍须从公网验证。

`Prepare-UpdateRelease.ps1` 默认 `-Mode exe-only`；`files` 模式需 `-ManagedFiles` 指定 JSON 数组，条目为 `path/allowCreate`，还可用 `-BasePackages` 或 `-BaseManifests` 指定官方旧包／签名清单的路径数组文件。工具据此生成可信旧文件哈希列表，不把玩家当前文件猜成可覆盖的官方资源。首版目标白名单为主 EXE、根目录 DLL、`sounds/` 单层音频；不支持删除文件，不允许配置目录。更新器协议、最低适用版本、.NET 运行时、平台和配置兼容标识不符时拒绝自动替换。

客户端使用 `.shike-updates/` 保存隔离会话、恢复材料和安装目录的版本记录。中断事务会阻止普通启动混合文件；需要人工恢复时，关闭所有目标实例后使用该会话原 `runner.exe --recover-update <session.json绝对路径> <会话token>`，恢复仍不绕过强制更新。正常异常会自动整批恢复；不承诺任意断电情况下都能自动恢复。更新成功后的已完成会话会在后续启动中安全清理。

`Run-WpfUpdateAcceptance.ps1` 用当前项目版本和仅用于测试的下一版本构建同一正式 App，复用真实启动检查、实际更新提示、下载校验、退出许可、助手和新窗口健康确认；只在带归属标记、nonce 和 EXE 哈希匹配的隔离副本中使用本地 HTTP 处理器。验收始终禁止原生输入、热键、外部浏览器和后台服务请求；正常程序不启用该适配器。测试版不公开，不能把此项称为原始旧版二进制或线上玩家更新已验收。

根目录只收录项目入口、Git 规则与 `源码/`。新增工具、源码和资源放在 `源码/` 下；截图、开发文档、配置、日志和构建产物留在本地。克隆后执行上面的 `core.hooksPath` 设置即可启用检查，提交和推送时会列出超出范围的文件。新功能确实需要扩大公开目录或文件类型时，同时更新 `.gitignore` 和 `.githooks/check-files`。
